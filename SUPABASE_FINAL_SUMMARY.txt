🔐 SEGURANÇA
═══════════════════════════════════════════════════════════════════════════

Row Level Security (RLS) está ATIVADO:
   ✅ SELECT (Leitura): PÚBLICO - anyone pode ler
   🔒 INSERT/UPDATE/DELETE: AUTENTICADO - apenas usuários logados

Isso significa:
   • Seu site pode ler dados publicamente (sem autenticação)
   • Apenas admins autenticados podem modificar dados
   • Perfeito para um painel admin futuro

🎯 PRÓXIMOS PASSOS NO APP
═══════════════════════════════════════════════════════════════════════════

1. Adicione variáveis de ambiente (.env.local):
   NEXT_PUBLIC_SUPABASE_URL=sua_url_aqui
   NEXT_PUBLIC_SUPABASE_ANON_KEY=sua_chave_aqui

2. Use a biblioteca Supabase em seu app:
   import { createClient } from '@supabase/supabase-js'
   const supabase = createClient(url, key)

3. Faça queries:
   const { data } = await supabase.from('recipes').select('*')
   const { data } = await supabase.from('ingredients').select('*')

4. Deploy:
   git add . && git commit -m "feat: Supabase migration with 431 recipes" && git push

❓ TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

"Table already exists"
   → Normal se rodar 2x. Use DROP TABLE IF EXISTS ou ignore.

"Permission denied"
   → Verifique as permissões do usuário. Use chave service_role só no backend.

"Dados não aparecem no app"
   → Verifique .env.local com URL e chave
   → Confirme RLS "Allow public read" está ativo
   → Teste no SQL Editor manualmente
